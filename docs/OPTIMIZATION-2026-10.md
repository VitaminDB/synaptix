# Оптимизация моделей: MXFP8/NVFP4, слитые ядра (октябрь 2026)

Живой трекер. Карта — RTX 5090 Laptop (sm_120, 24 ГБ). Замеры — кодом службы
(`synaptix-gen`, примеры `gen_video` / `gen_image`) или `synaptix h3` с метками
фаз; профиль ядер — `nsys profile -t cuda --delay … --duration …`.
Правило качества (см. `LTX_GEMM_PARITY.md`): бит-в-бит либо визуальная сверка.

## Сделано

### MiniMax-H3
- **Кэш adaLN на диске** (`adaln_disk.rs`): проекции adaLN 50 блоков — 52 ГБ
  bf16 (2/3 файла), результат зависит только от таймстепов. Повтор с теми же
  шагами — бит-в-бит из `~/.cache/synaptix/h3-adaln` (служба —
  `/var/cache/synaptix`): 25.5 → 0.3 с. Первый прогон — загрузка проекций
  pinned-конвейером: 26.5 → 19.7 с (упор — чтение NVMe).
- **Слитые ядра блока** (бит-в-бит, тест `cuda_seg_mod`):
  `rms_segmod_quant` (норма + сегментная модуляция + квант по таблице строк,
  без развёрнутых [токены × 5376] scale/shift и без записи нормы),
  `gate_residual_seg` (одним запуском), `qk_norm_rope` (qk-норма + RoPE в bf16
  без F32-проходов), `silu_mul_quant_mxfp8`.
- Денойз 640×384, 2 с, 20 шагов, NVFP4: **20.0 → 15.5 с**, видео и звук
  бит-в-бит. MXFP8 — тот же слитый путь (работает, ≈1.45 с/шаг: cp.async-GEMM
  на K=5376).
- Говорящий аватар (ref2va 1344×768, 3.8 с): 473 → 450 с; шаг 18.3 → 17.4 с —
  на большом разрешении шаг почти целиком внимание.
- **Декод видео-VAE** (ViT, 36 блоков, тайлы 256 px): каждый matmul копировал
  транспонированный вес и шёл в NN-GEMM → `linear` (TN, без копии; бит-в-бит),
  затем bias в эпилоге GEMM, qk-норма + RoPE одним ядром прямо в BSHD и
  flash BSHD без транспонирований (PSNR 48 дБ к прежнему — f32 внутри вместо
  округлений bf16). 1344×768×90: **49 → 28.6 → 25.5 с**. Остаток — BF16 GEMM
  на ~80 TFLOP/s (предел железа).

### MXFP8 с BF16-активациями (все модели через `QuantLinear`)
- GEMM MXFP8 с выходом BF16 (`-DSYN_OUT_BF16`), квант активации из BF16, без
  предмасштаба (E8M0 не насыщается) и без кастов f16↔bf16; prequant MXFP8 для
  K вне кратности 512. Тест: расхождение с f16-путём ≤ 1 ulp bf16.

### LTX-2.3 липсинк
- Замороженный звук: скалярная сигма модальности = 0 (как
  `modality_from_latent_state` эталона Lightricks при `state.frozen`) —
  prompt-AdaLN звука и гейты кросс-внимания звук→видео.
- LipDub: новая речь — замороженный основной звук обеих стадий, референс —
  звук исходника. Раньше губы шли за речью, сгенерированной по промпту, и
  копировали исходник (корреляция раскрытия рта с новой речью −0.20 → +0.15).

### Внимание
- `flash_splitq` v5 в BSHD (по `SYN_FLASH_V5_BSHD=1`): на форме H3 не быстрее
  v1 (87.6 vs 82.2 TF в бенче `bench_flash_layout`). В составе DiT обе версии
  ≈58 TF — карта упирается в лимит мощности при длительной нагрузке.

### FP8-внимание (`flash_fp8.cu`)
- QKᵀ и P·V на e4m3-mma (f32-аккумулятор): Q/K по токену (у K вычтено
  среднее по токенам), V по каналу, P·448; V транспонирована с перестановкой
  ключей — C-фрагменты S сразу A-фрагменты. Ошибка против bf16: 0.3–0.4%
  (cos ≥ 0.99999), тест `cuda_flash_fp8`.
- Бенч (с квантом): форма H3 4316×42 — 4.54 → 2.99 мс; 25200×42 — 146 → 92 мс
  (≈1.5–1.6×). Режим «только QK» выигрыша не даёт (bf16-тайл V).
- Включается для потока (`precision::set_attention_fp8` / `AttentionFp8Guard`,
  `SYN_ATTN_FP8=0|1`): bf16, hd128, без маски/GQA, обе длины ≥ 256 — в BSHD и
  BHSD. `synaptix-gen` включает при квантованном трансформере (H3, LTX,
  картинки).
- H3 640×384: денойз 15.5 → 13.3 с. Аватар 1344×768: 473 → 321 с (шаг
  18.3 → 12.1 с). Qwen-Image 2.1 NVFP4: 17.0 → 15.6 с. LTX-2.3 1280×704 4 с:
  bf16 84.5 с → NVFP4+FP8 49.3 с. Визуально равноценно.

### MXFP8 rot для K, кратного 128
Шкалы drot читают producer-варпы (`SF_LDG`: `ld.global` в регистры до
ожидания empty → `st.shared` → `mbarrier.arrive`), а не TMA-окна по 16 Б —
TMA требовал K%512. Бит-в-бит с cp.async-ядром (стресс-тест 100 повторов);
`cp.async` + `arrive.noinc` и `setmaxnreg.dec 24` давали редкие расхождения —
поэтому синхронные `st.shared` и 40/232 регистров. Быстрее и TMA-окон →
по умолчанию для всех K (`SYN_MXFP8_TMA_SF=1` — прежние). H3 MXFP8: шаг
1.5 → 1.2 с; Qwen-Image 2.1 MXFP8 денойз 19.5 → 16.2 с.

### Загрузка H3
Сырые веса блоков DiT и энкодера шли pageable-копией из mmap (1.7 ГБ/с):
теперь pinned-конвейер + прогрев page cache следующего блока / тензоров
энкодера (`prefetch.rs`, `MADV_POPULATE_READ` в 16 потоках) параллельно с
H2D. С холодного диска: энкодер 15.3 → 11.5 с, блоки 15.6 → 10.1 с.

### FLUX.1 / FLUX.2
FP8-внимание получило F16-вариант (`-DFA8_F16`) — FLUX.1 считает в F16 и
раньше шёл мимо FP8. Gated residual и модуляция одним ядром, FP8-внимание в
BSHD без транспозиций, у FLUX.2 общий квант входа q/k/v (бит-в-бит).
FLUX.1 NVFP4 шаг 0.53 → 0.40 с, bf16 53 → 45 с; FLUX.2 base-4b NVFP4
30.1 → 27.2 с, MXFP8 33.3 → 30.1 с.

### FP8-внимание по формату файла, слитые qk-норма + RoPE у FLUX.1 (14.10)
- FP8-внимание включалось только по запрошенному кванту: модели из
  квантованных бандлов библиотеки (MXFP8 по политике) без явного кванта шли
  bf16-вниманием. Теперь — по формату трансформера в `quant_manifest.json`
  (картинки, LTX; у H3 и так). FLUX.1 MXFP8 1024², 28 шагов: **27.7 → 20.6 с**.
- LTX-2.3 без явного кванта берёт формат бандла (MXFP8): раньше MXFP8-файл
  деквантовался в плотный BF16 и стримился с хоста.
- `qk_norm_rope` — режим RoPE парами (FLUX, таблицы `[S, D]`), норма и
  поворот в F32 одним проходом; бит-в-бит с F32-эталоном (тест
  `qk_norm_rope_interleaved_bitexact`). FLUX.1: rms_norm + rope 383 мс →
  156 мс на 5 с профиля (−4.5 % GPU), 20.6 → ~20.2 с; к прежнему пути
  визуально равноценно (без промежуточного округления до bf16).
  `SYN_FLUX_NORM_ROPE_SPLIT=1` — прежний путь.

### MiniCPM-V 4.7 (15.10)
Поддержка обеих моделей (см. `minicpm_v47.md`): MoE-эксперты в гибридном
декодере с device-маршрутизацией на шаге декода (резидентно 92 → 103 ток/с у
35B-A3B), офлоад экспертов под башню зрения, кэш экспертов в медиа-пути
(декод с картинкой 16 → 74 ток/с), маленькие плотные модели без кванта на
загрузке (1B: F16 198 ток/с при качестве bf16-эталона). Очередь: слитые ядра
блока GDN + silu-MoE — шаг декода 35B упирается в ~4000 мелких ядер.

## Замеры для сравнения

| модель | режим | bf16 | MXFP8 | NVFP4 |
|---|---|---|---|---|
| Qwen-Image 2.1 1024², 40 шагов | денойз | 34.9 с | 19.5 с | 17.0 с |

Профиль Qwen-Image NVFP4: внимание 29%, GEMM 24%, остальное — предмасштаб
`QuantLinear` (abs/max/broadcast_mul ×2), отдельный квант на каждую из q/k/v,
`silu_and_mul` + копии половин gate/up, rms_norm qk, rope.
