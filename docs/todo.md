## Производительность моделей — приоритет невысокий

Общая задача: пройтись по используемым моделям и ускорить их (свои ядра, слияние операций, кэши, кванты).
Каждый шаг — с записью «было → стало» в `docs/performance.md`.

- **MiniMax Music 3** (сейчас 32 с песни ≈ 3 мин):
  - сочинение 10,5 кадр/с при нужных 25: обе ветки CFG одним проходом LM (flash-ядро внимания не держит пакет 2 —
    исправить ядро), KV-кэш в локальной LM (сейчас вся последовательность заново, 7 проходов на кадр), сэмплинг на
    карте без 8 синхронизаций на кадр, захват графа декода;
  - звук ~3 с на секунду: cond/uncond одним пакетом, слитые ядра блока трансформера, квант MXFP8;
  - квантовать трансформер (−5 ГБ в бандле).
- **Hy4-flash** — когда свободна видеокарта, например в ночь на субботу: декод экспертов (промахи слотов по PCIe),
  DFly2 с выигрышем, префилл с картинкой (25–37 с на ~1,7 тыс. токенов). См. `docs/hy4_flash.md`.
- **LTX-2.5**:
  - диффузионный декодер: ядро внимания по окрестности — простое (варп на пару токен–голова), без общей памяти и
    тайлов ключей; DFR + декодер 1344×768 × 5 с — 130 с против 87 с с VAE;
  - этап 2 DFR перезагружает DiT с LoRA — держать второй вид весов или прибавлять LoRA на лету.
- **MiniMax-H3**: сцена 10 с на 1344×768 — ~65 с/шаг, упор во внимание; служба в ~1,3 раза медленнее CLI
  (энкодер Qwen3-VL стримит слои с диска после вытеснения кэша страниц, запас подстройки 2 ГБ).
- **Qwen-Image, FLUX, YuE2, ACE-Step, TTS/ASR** — сначала снять замеры (в таблице их нет), потом решать.

## LTX-2.5 — недоделанное
- Улучшитель промпта в режиме «по картинке».
- Временные раунды DFR (48/96 кадр/с с доводкой) и пространственный эпилог (4K).
- Декодер с ключевыми кадрами (`decode_with_keyframes`).
- Версия dev и дистилл-LoRA — по слову пользователя.
