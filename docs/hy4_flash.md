# Hy4-flash (tencent, `hy_v4_flash`)

220 млрд параметров (63,5 млрд — engram), 12 млрд активных на токен, контекст 1M. Оригинал BF16 —
`~/Storage/Нейросети/Модели/_hf/Hy4-flash` (148 шардов, 440 ГБ; не удалять). Крейт —
`crates/synaptix-models/llm/hy_v4_flash`, ядра — `synaptix-kernels-cuda/src/cu/fused/hy4.cu`.

Эталоны: transformers PR #50903 (`modeling_hy_v4_flash.py`) и vLLM (`vllm/models/hy_v4_flash`,
`vllm/models/hy_v4`). Где они расходятся (engram), движок следует vLLM.

## Архитектура (text_config)

- 42 слоя, hidden 3072, словарь 120832, RMS eps 1e-5. Слой 0 — плотный MLP (13824), 1–41 — MoE.
- **iHC** (identity Hyper-Connections, 4 потока `[T, 4, H]`): `mixes = flat(X)·fnᵀ · rsqrt(mean(X²)+eps)`;
  `pre = σ(mix·s0 + b) + 1e-6`, `post = 2·σ(mix'·s1 + b') + 1e-6`; вход подслоя `Σ pre_i·X_i`,
  возврат `X_i += post_i · y`. Голова: те же 4 `pre`, затем `model.norm` и `lm_head`.
  Веса: `hc_attn_layer.hc_pre.hc_{fn,base,scale}`, `hc_mlp_layer…`, `hc_head.hc_head_*` (F32).
- **Внимание** — MLA с гейтом и синками: `q = q_b(rms(q_a(x)))` (q_lora 1024), `ckv = kv_a(x)` →
  латент 512 (`kv_a_layernorm`) + `k_rot` 64; `kv_b` → `k_nope` 192 и `v` 256 на голову; RoPE —
  чередующиеся пары на последних 64 каналах q/k; масштаб `1/16` (qk 256); синк на голову —
  лишний логит без value; выход `·σ(linear_gate(x))`, `o_proj`, затем `post_proj_norm`.
  - `sliding_attention` (30 слоёв): 64 головы, окно 512 (своя позиция и 511 прошлых), θ = 1e4.
  - `deepseek_sparse_attention` (12 слоёв: 0, 1, 5, 9, …, 41): 32 головы, θ = 1e7, сжатый индексатор:
    ключ токена `rms(token_key_projection(x))` (128), группы по 4 токена свёртываются
    (`softmax(Wg·k + ape)` по слотам × `Wv·k`, `key_norm`, RoPE на позиции первого токена группы),
    запрос `query_projection(q_resid)` 16×128 с RoPE, оценка `Σ_h w_h·relu(q_h·K_g)`
    (`w = head_weight_projection(x)·16^-½·128^-½`), выбор top-511 закрытых групп раньше своей
    плюс своя. Пока прошлых групп ≤ 511 — это плотное каузальное внимание.
- **MoE** латентный: роутер на полном x (σ, поправка выбора `e_score_correction_bias`, top-16 из 512,
  нормировка, ×3,998); эксперты в ширине 1536: `routed_expert_down_proj` (3072→1536) → эксперты
  (`silu(min(g,10))·clamp(u,±10)`) → `routed_expert_up_proj` (1536→3072); общий эксперт (1536,
  без ограничения) на полном x; сумма → `combine_output_norm`. У плотного слоя — `post_fc2_norm`.
- **Engram** (слои 1, 11, 21, 31 — перед вниманием): id → `lookup_table` (карта нормализованного
  словаря, I32), 2- и 3-граммы `[t, t−1, t−2]` (за началом — заполнитель), `rolling ^= id_s·mult_s`,
  по 8 голов на порядок: строка `rolling mod prime + offset`. Таблица `[164994380, 96]` на слой.
  Строки норм. по головам (eps F32), `value_proj`/`key_projs.c` (1536→3072, со смещением),
  гейт потока `σ(sign·√max(|⟨rms(k_c)·kn_c, rms(X_c)·qn_c⟩/√H|, 1e-6))`,
  `X_c += (gate + hc_scale_c)·pre_gamma·rms(value)`. Заполнитель (`engram_pad_id`) памяти не получает.
  Множители хэша эталон тянет из `numpy.random.default_rng(seed + 10007·id)` с границей по
  `max(lookup_table)+1` — посчитаны один раз и лежат в `hy4_engram.json` (кладётся в каталог HF
  до упаковки и попадает в бандл).
- DFly2 (`model.dfly_layers.*`) — спекулятивный драфтер, башня зрения `vit.*` — разделы ниже.

Расхождения эталонов: у transformers `nn.RMSNorm` engram без eps → eps bf16 = 2⁻⁷ (заметно на строках
таблицы ~1e-2); vLLM — eps F32. vLLM также отображает id вне карты в себя (transformers — в заполнитель).

## Бандл

```sh
cp scratchpad/hy4_engram.json _hf/Hy4-flash/   # множители хэша engram
synaptix quantize _hf/Hy4-flash llm/hy4-flash.syn --policy llm \
  --rule compressed_indexer.=none --rule vit.=none
```

Эксперты NVFP4 (~85 ГБ), внимание, общие эксперты, крайние слои, эмбеддинг, голова и engram-таблицы —
MXFP8; индексатор (F32-проекции, позиционная таблица) и зрение — как есть. Engram-таблица 31,7 ГБ
одним тензором кодируется кусками строк (`SYN_QUANT_ROW_CHUNK`).

## Движок

- Потоки iHC — F32; проекции — BF16 на квант-весах; эксперты — F16 через общий `MoeFfn`
  (`MoeExt::router_hidden`, `Activation::SiluClamp`), лениво из бандла с кэшем на карте
  (`SYN_HY4_EXPERT_CACHE_GB`, 8) и зеркалом в RAM (сколько влезает).
- Внимание — поглощённая форма по латентному кэшу (`q_lat = q_nope·W_uk`, `v = o_lat·W_uvᵀ`, W из
  `kv_b_proj` в BF16): ключей на запрос не больше 2048, ядро `hy4_mla_attn` держит оценки в shared.
  Кэш индексированных слоёв — F32 (`HY4_KV=bf16`), у SWA — кольцо окно + чанк префилла.
- Engram: хэш и строки таблицы — на хосте (строки MXFP8 читаются из блобов бандла), гейт — на карте.

Фасад: `synaptix run llm/hy4-flash.syn "…" --chat` — шаблон по умолчанию с рассуждениями
(`reasoning_effort:high`, ход начинается внутри `<think:opensource>`); теги фасад берёт по словарю
(`facade::chat::think_tags`: `</think:opensource>` — один токен → теги Hy4). Шаблон использует
Python `str.format` — поддержан в `pycompat`.

Декод (RTX 24 ГБ, `hy4_run --wait-mirror`, после заполнения зеркала):

| шаг | ток/с | что дало |
|---|---|---|
| первый живой прогон | 5,7 | — |
| `hy4_head_gemv` — поглощённые проекции MLA ядром по головам | 9,8 | 79 → 1,3 мс/токен |
| строки engram всех слоёв разом, параллельно | 12,7 | 28 → 3,6 мс/токен |
| кэш экспертов на всю свободную VRAM | 15,4 | |
| zero-copy декод MoE (роутинг на карте, промахи из закреплённой RAM) | 16,9 | точнее: KL к префиллу 0,05 против 0,11–0,24 |

Префилл короткого промпта — 2 с (сразу после загрузки, пока зеркало заполняется, ~20 с: эксперты
идут с диска). Сверка с BF16-эталоном: top-1 совпадает, cos по слоям 0,996 → 0,80 (шум
MXFP8/NVFP4); выбор групп индексатора на 2600 токенах совпадает на 98–99,6 %. Упор декода — шина:
промахи слотов zero-copy (26–34 %) читаются из RAM. Замеры шумят, если машина загружена, и потому, что
при закреплённом зеркале (~75 ГБ) таблицы engram (~63 ГБ) не помещаются в кэш страниц.

Переменные: `SYN_HY4_ZC` (zero-copy, 1), `SYN_HY4_ZC_MIN_SLOTS` (16), `SYN_HY4_ZC_HEADROOM_MB` (2048),
`SYN_HY4_ZC_DECODE_CACHE_MB` (2560), `SYN_HY4_ZC_PREFILL_GB` (2,5), `SYN_HY4_ZC_RELEASE` (1024 токенов),
`SYN_HY4_EXPERT_CACHE_GB` (без zero-copy; по умолчанию — свободная VRAM − `SYN_HY4_VRAM_RESERVE_GB`),
`SYN_HY4_MIRROR` (1), `SYN_HY4_CHUNK` (2048), `HY4_HEAD_GEMV` (1), `HY4_KV=bf16`. Профиль —
`SYN_MOE_PROFILE=1` (стадии с синхронизацией), `SYN_HY4_TRACE_MEM` — VRAM перед слотами,
`HY4_VERBOSE` — форматы проекций, `HY4_STAGE_LAYER`+`HY4_DUMP` — стадии слоя для сверки.

## Картинки

Башня (`vision.rs`) — SigLIP-so400m без pre/post-LN и без 2D RoPE: патчи 16×16 (вектор `[c][ky][kx]`),
позиции — таблица 128×128, билинейно с масштабом `(g + 0.1)/128` (`align_corners=False`), 27 pre-LN
блоков (LayerNorm с bias, полное внимание 16×72, точный GELU). Адаптер `perceive`: RMSNorm → свёртка
2×2 (канал старший, затем dy, dx; 1152 → 4608) → GELU → 1×1 (→ 3072) → столбец `image_newline` в конце
каждой строки. Препроцесс: smart_resize (кратность 32, площадь 4096…2048², банковское округление),
бикубик с антиалиасом по uint8, `u8/127.5 − 1`. Токенов `N = (H/32)·(W/32 + 1)`, в тексте
`120118, 120120 × N, 120119`; признаки встают на места 120120 без масштаба; engram на них без памяти.

Текстовая модель с картинками — M-RoPE (`mrope_section [12,10,10]`, чередующиеся пары): пара j < 30
берёт ось `j % 3` (t, h, w), остальные — t; во всех слоях и в индексаторе (ключ группы — позиция
её первого токена, таблица RoPE-позиций слотов на карте). Заполнитель k картинки `rows × cols`:
`(s, s + k/cols, s + k%cols)`; следующий токен `s + max(rows, cols)`, дальше «максимум + 1». Окна и
каузальность — по слотам. Без картинок все оси равны позиции — путь текста прежний.

Сверка башни: `hy4_vision` + `scripts/reference/hy4_vision_ref.py` — визитка 1193×1366 → 1634 токена,
cos к эталону 0,99974. `hy4_run --image файл --chat "…"`, `synaptix run --image`, служба
(`MEDIA=файл synaptixctl gen hy4-flash …`) — визитку читает по содержимому. Префикс из кэша с
картинками — только при тех же отпечатках.

## Драфтер DFly2

5 слоёв MLA без iHC (32 головы, θ = 1e7, синки, гейт, post_proj_norm; FFN — dense SwiGLU 9216 без
ограничения). Слой драфтера `i` читает латентный кэш целевого слоя 25/29/33/37/41, разворачивая его
своим `kv_b_proj`, и пишет туда латенты своего блока; ключи строки — выбор групп индексатора цели для
последнего принятого токена (снимок `LayerCache::snap`) плюс отрезок от начала его группы до позиции
строки (`Keys::Draft`). Блок `[bonus, mask 120009 × K]` на позициях `a … a+K` — один проход с каузальной
маской; строка 0 смешивается с финальным скрытым цели (`mtp_fusion` slot0), драфты — из строк 1…K через
`hidden_correction` с эмбеддингом предыдущего токена и lm_head цели. Эмбеддинги и голова — цели.

`SYN_HY4_DFLY=1 hy4_run … --spec K`: жадная спекуляция с откатом кэша; текст совпадает с обычным
декодом. Приёмка: код 54–72 % (3,1–3,7 токена за шаг), проза 22–25 %. Выигрыша нет: верификация
блока упирается в шину (эксперты всех строк блока из RAM) — 196 мс на 4 строки против ~55 мс на шаг
(код — 15,3 ток/с против 16,9). Имело бы смысл, когда эксперты целиком на карте. Веса драфтера в
бандле (MLP и hidden_correction — NVFP4) против BF16 оригинала (`SYN_HY4_DFLY_FROM`) приёмку не меняют.

Проверка: `cargo run --example hy4_run -- llm/hy4-flash.syn --chat "…" --gen 64`;
сверка: `HY4_DUMP=dir … --save-ids ids.txt`, затем `scripts/reference/hy4_ref.py --ids ids.txt --out ref/`
и `hy4_cmp.py ref/ dir/`.
