# MiniCPM-V 4.7 (OpenBMB, октябрь 2026)

Две модели семейства: **35B-A3B** (MoE: 256 экспертов, 8 активных, 40 слоёв,
~70 ГБ bf16) и **1B** (плотная, 1.55B, 3.1 ГБ bf16). Обе —
`model_type = minicpmv4_7`, контекст 262 144, Apache-2.0, HF:
`openbmb/MiniCPM-V-4.7-35B-A3B`, `openbmb/MiniCPM-V-4.7-1B`.

## Как устроена

- **Текст** — гибрид Qwen3.5 (`text_config.model_type` `qwen3_5_moe_text` /
  `qwen3_5_text`): GatedDeltaNet + полное внимание каждый 4-й слой,
  `attn_output_gate`, partial RoPE 0.25, M-RoPE `[11, 11, 10]` с интерливингом.
  Исполняется конвейером `synaptix-llm-qwen3-next-hybrid`; у 35B вместо
  плотного MLP — Qwen-MoE (`mlp.gate` роутер, стопки
  `mlp.experts.{gate_up_proj,down_proj}`, `shared_expert` с sigmoid-гейтом) —
  общий декодер получил `Ffn::Moe` (`synaptix_llm_common::model::Ffn`,
  спецификация `DecoderExt::moe_ffn`). Веса MTP в чекпоинте отсутствуют.
- **Зрение** — крейт `synaptix-vlm-minicpm` (`crates/synaptix-models/vlm/minicpm_v`):
  SigLIP 27 слоёв (1152, патч 14, NaViT без фиксированного размера, позиции
  по ближайшему соседу из таблицы 70×70), после 7-го слоя — оконный
  объединитель 2×2 (`vit_merger`: внимание внутри окна + MLP 4D→D с
  остатком-средним), `post_layernorm`, затем `model.merger.mlp.0` (ещё 2×2 →
  LLM-размерность, GELU точный). Итого 16 патчей → 1 токен.
- **Препроцессинг** — как `MiniCPMV4_6ImageProcessor`: миниатюра
  (`find_best_resize`, масштаб 448, стороны кратны 56) и до 9 срезов
  (`get_sliced_grid` по log-ratio), бикубический ресайз с антиалиасингом,
  нормализация `(x − 0.5)/0.5`.
- **Промпт** — `<image_id>N</image_id><image>…</image>` и строки
  `<slice>…</slice>` через `\n`; номер картинки проставляется при рендере
  chat-шаблона (`facade::llm::number_image_ids`, метка
  `MINICPM_IMAGE_ID_MARK` в `prompt_block`).
- **Позиции** — «холстовый» M-RoPE (`mrope_mode = canvas`): миниатюра
  растягивается на холст срезов, `<image>`/`</image>`/`<slice>`/`</slice>`/`\n`
  прибиты к углам (порт `get_rope_index` — `synaptix_vlm_minicpm::layout::canvas_positions`;
  id токенов — `HybridConfig::canvas`).

## Сверка с transformers 5.19 (1B, CPU f32 против synaptix bf16, greedy)

- Текст: первые 32 токена ответа совпадают бит в бит.
- Картинка 319×189 (миниатюра 24×40 патчей, 60 токенов, без срезов): первые
  ~20 токенов ответа слово в слово, дальше расхождение округления bf16/f32.
- Картинка 1024² (миниатюра 32×32 + 6 срезов 40×24 сеткой 3×2, 424 токена,
  холст с `<slice>` и `\n`): все 40 токенов ответа слово в слово.
- Эталон: `uv venv` + torch cpu + transformers 5.19 + torchvision, скрипт
  `ref.py` (greedy, top-5 логитов, позиции M-RoPE, дамп логитов).

## Скорость (RTX 5090 Laptop, 1B)

| профиль | текст, декод | картинка 424 ток, префилл / декод |
|---|---|---|
| плотный F16 (optimal для < 4 ГиБ) | 198 ток/с (граф) | 3540 ток/с / 190 ток/с |
| плотный BF16 (без графа) | 84–98 ток/с | 2990 / 84 |
| NVFP4 на загрузке | 318 ток/с, но речь ломается («интелм из машиней») | — |

35B-A3B (NVFP4 эксперты, MXFP8 остальное, 22 ГБ): резидентно — загрузка 4 с,
декод ~103 ток/с, префилл ~240 ток/с; но резидентные веса занимают 23.1 из
24.4 ГБ и башне зрения места нет, поэтому фасад (`vlm_offload_guard`) грузит
такой бандл с экспертами в RAM и кэшем на карте: декод 65–74 ток/с, с
картинкой 424 токена — префилл 210 ток/с, декод 74 ток/с (через службу: 56
ток/с, 17 с на ответ с загрузкой). `SYN_OFFLOAD=resident` — принудительно
резидентно (текст без картинок).

Профиль декода 35B резидентно (`SYNAPTIX_LLM_PROF=1`, синхронный, 120 токенов,
до слитого пути): linear-attention 24.5 % (0.17 мс/слой — 7 ядер), MoE 21 %
(0.11 мс/слой — роутер, top-k, два индексных GEMV, shared-эксперт), полное
внимание 12 %, нормы/остатки/RoPE — мелкие ядра по 7–40 мкс; ~45 запусков на
слой.

**Слитый шаг блока гибрида** (`DecoderModel::forward_block_fused_hybrid`,
F16, Blackwell): хвост после внимания одним ядром сразу в трёх видах (NVFP4-
пара для экспертов, пара формата shared-эксперта, строка для роутера), роутер
вместе с логитом sigmoid-гейта shared-эксперта (матрица `[E + 1, H]`), gate|up
shared одним GEMV, silu·up + top-k одним ядром, эксперты — индексный GEMV
gate|up → silu с квантом → индексный GEMV down с f32-суммой, хвост FFN с
гейтом shared и нормой входа следующего слоя (строка + MXFP8-пара под его
проекции); линейное внимание — групповые GEMV четырёх проекций (два запуска)
→ ядро GDN-шага → `out_proj`. ~14 запусков на слой. Ядра хвостов стали
шаблонными по типу (bf16/f16), geglu получил silu, роутер — f16-вход. Под
графом гибрида: **103 → 120 ток/с** (текст, резидентно); граф для MoE-
гибридов включён в профиле по умолчанию. Плотные гибриды (Qwen3.8-27B) от
слияния не выигрывают — они упираются в чтение весов (30.6 против 30.0), им
граф по-прежнему выключен. С экспертами в RAM (служба с картинками) слитый
путь не применим: маршрутизация идёт через хост.
`SYN_FUSED_DECODE=0` — прежний путь, `SYN_GRAPH_NOCAPTURE=1` — device-шаг без
захвата (для профиля по операциям).

Телефон (Xiaomi 12T Pro, CPU, q8row int8): загрузка ~10 с (с башней ~25 с),
текст — декод ~5.5 ток/с, картинка 60 токенов — префилл 2 с, декод 5 ток/с.
